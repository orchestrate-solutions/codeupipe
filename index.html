The Manifesto

Complexity in software arises when concerns are tangled. Codeupipe protects codebases from architectural rot by decoupling computation, routing, telemetry, and non-blocking events — so any engineer, or any agent, can reason about system behavior effortlessly.

Immutable Data Flow over in-place mutation
Declarative Composition over procedural routing
Detached Concurrency over blocking side-effects
Inspectable Blueprints over runtime black boxes
That is, while there is value in the items on the right, we value the items on the left more.

System Overview

CUP separates concerns across two operational planes. The Synchronous Conveyor is your core transaction — fast, unblocked, deterministic. The Detached Boundary is where instrumentation, events, and out-of-band work live.

Synchronous Conveyor

The core transaction moves down the belt.

  • Payload — the immutable envelope
  • Filter — one Payload in, one Payload out
  • Pipeline — the ordered blueprint
  • Valve — conditional gate on a step

Detached Boundary

Observation and side effects — never blocks the belt.

  • Tap — read-only observer
  • Hook — before / after / on_error lifecycle
  • State — execution metadata (never Payload)

The Seven Primitives

Every CUP concept fits in one of these seven boxes. Click any card for the full contract.

Payload the envelope

Immutable data container. Keyed. Every write returns a new Payload.

Contract: get(key) → value or null-equivalent (never raises). insert(key, v) → new Payload; original unchanged.

Invariant: A Filter never mutates its input Payload.

Filter the station

Atomic unit of work. One method: call(payload) → payload.

Contract: Pure-ish. Same input Payload → same output. One class per file, PascalCase class / snake_case filename.

Invariant: A Filter always returns a Payload — never null, never omits.

Pipeline the conveyor belt

An ordered list of Filters. The Pipeline is data, not code.

Contract: run(payload) threads the Payload through each step. Nesting legal — a Pipeline is a step.

Invariant: Steps execute in declared order.

Valve the diverter

Conditional gate. Wraps a Filter with a pure predicate.

Contract: Predicate payload → boolean. True → run. False → pass-through.

Invariant: Branching lives in the Pipeline, never inside a Filter.

Tap the camera

Read-only observer. Sees the Payload. Returns nothing.

Contract: on_payload(payload) → void. Cannot mutate. Async handoff for heavy I/O.

Invariant: Removing all Taps yields identical output.

Hook the safety system

Lifecycle callbacks: before, after, on_error.

Contract: Fires at Filter boundaries. on_error may return retry | skip | propagate.

Invariant: A Hook that raises is a bug in the Hook.

State the clipboard

Execution metadata: step count, timings, errors, retries.

Contract: Available to Hooks and Taps. Not visible to Filters. Never carries domain data.

Invariant: Filters do not read or write State. Ever.

Same pipeline in three languages

Python

class Trim(Filter):
    def call(self, p):
        return p.insert(
            "text", p.get("text").strip()
        )

pipe = (Pipeline()
    .add_filter(Trim())
    .add_filter(Upper()))
out = pipe.run(payload)

TypeScript

const Trim = {
  call: (p) => p.insert(
    "text", p.get("text").trim()
  ),
};

const pipe = new Pipeline()
  .addFilter(Trim)
  .addFilter(Upper);
const out = await pipe.run(payload);

Rust

struct Trim;
impl Filter for Trim {
  fn call(&self, p: Payload)
      -> Payload {
    let t = p.get_str("text").trim();
    p.insert("text", t)
  }
}
let pipe = Pipeline::new()
    .add_filter(Trim)
    .add_filter(Upper);
let out = pipe.run(payload)?;
